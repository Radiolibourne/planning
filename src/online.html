                Mettre en ligne pour l'équipe

                Environ 30 minutes, gratuit. Deux services : Firebase (Google) garde les données, GitHub Pages héberge la page. Conseil : créez-les avec une adresse Gmail dédiée au service (par exemple planning.radio…@gmail.com) plutôt qu'avec une adresse personnelle.

                A. Créer la base de données (Firebase)

                1. Ouvrez console.firebase.google.com, connectez-vous, puis Créer un projet (nom : planning-radio). Google Analytics : désactivé.
                2. Firestore Database → Créer une base de données. Emplacement : europe-west9 (Paris). Mode : production.
                3. Authentication → Commencer → Adresse e-mail/Mot de passe → Activer. Puis onglet Utilisateurs → Ajouter un utilisateur : votre adresse et un mot de passe solide. Copiez la valeur UID utilisateur de la ligne créée et collez-la ci-dessous. Faites de même pour un second administrateur si vous le souhaitez (un UID par ligne).
                1. Paramètres du projet (roue dentée) → Vos applications → icône </> (Web), nom planning, sans cocher Hosting. Copiez tout le bloc firebaseConfig et collez-le ici :
                1. Choisissez le code d'équipe que les médecins saisiront pour accéder au planning. Il fait office de mot de passe commun : gardez-le long.
                1. Firestore Database → onglet Règles : remplacez tout le contenu par le texte ci-dessous, puis Publier.

                B. Mettre la page en ligne (GitHub Pages)

                1. Téléchargez la page configurée : index.html
                  Elle contient votre configuration Firebase (publique par nature), mais ni le code d'équipe ni les données du service.
                2. Sur github.com, créez un compte puis New repository : nom planning, Public, Create repository.
                3. Lien uploading an existing file → déposez index.html → Commit changes.
                4. Settings → Pages → Source : Deploy from a branch, branche main, dossier / (root) → Save. L'adresse https://votre-compte.github.io/planning/ apparaît en 1 à 2 minutes.
                5. Dans Firebase : Authentication → Paramètres → Domaines autorisés → Ajouter un domaine : votre-compte.github.io.

                C. Démarrer

                1. Ouvrez l'adresse, saisissez le code d'équipe, puis Admin → connectez-vous → Remplacer par un classeur mis à jour : déposez votre parametres_planning.xlsx.
                2. Envoyez à l'équipe l'adresse et le code d'équipe. Sur iPhone : ouvrir dans Safari → Partager → Sur l'écran d'accueil pour l'avoir comme une application.
                3. Testez l'ouverture depuis un poste de l'hôpital : certains réseaux hospitaliers filtrent les sites extérieurs.

                Si le code d'équipe circule trop : préparez de nouvelles règles avec un nouveau code (étapes 5-6), puis rechargez le classeur de paramètres et republiez le planning, car les données de l'ancien code ne sont plus accessibles.
                Pour modifier la page plus tard : téléchargez-la de nouveau ici et remplacez index.html sur GitHub.

                Planning radio sur votre écran d'accueil

                Ouverture en un geste, comme une application, même sans réseau.

                1. Touchez le bouton Partager en bas de Safari. Sur les iPhone récents, il se trouve dans le menu ⋯ en bas à droite.
                2. Faites défiler et touchez Sur l'écran d'accueil.
                3. Touchez Ajouter : l'icône « Planning radio » apparaît. Ouvrez ensuite le planning par cette icône.

                Vous êtes dans le navigateur d'une autre application (e-mail, messagerie) : ouvrez d'abord ce lien dans Safari.

                1. Touchez le menu ⋮ en haut à droite de Chrome.
                2. Touchez Ajouter à l'écran d'accueil (ou Installer l'application).
                3. Confirmez : l'icône « Planning radio » apparaît. Ouvrez ensuite le planning par cette icône.
